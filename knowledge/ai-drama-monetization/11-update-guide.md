# 更新规范

保持模块结构稳定，先登记新证据，再局部更新结论。不因数据暂缺而破坏收入树，也不为凑齐表格估算未知占比。

## 文件分层

- `knowledge/ai-drama-monetization/`：提炼后的模型、案例、方法、假设与更新规范。
- `references/ai-drama-monetization/`：来源、定位、口径及数据登记。
- `projects/active/ai-drama-research/`：过程、未完成验证与移交说明。
- 原始附件保持原位置只读；未经授权不提交全文、后台导出、凭据或个人明细。

## 新资料写入流程

1. 新增来源 ID，记录标题、作者、日期、原始入口、类型、原文定位、读取日期及核验限制。
2. 对新结论分类：用户数据、来源表述、推断、假设、建议或待核验；一段中混合时分别标明。
3. 涉及数字必须登记时间窗、币种/单位、分子、分母、统计粒度、去重、样本范围、毛/净与确认/回款口径。缺失写“未知”。
4. 只更新相关模块，给证据或数据 ID；有冲突并列保留新旧值及口径，不静默覆盖。
5. 更新假设状态与变更记录，检查相对链接、表格、重复计算和敏感信息。
6. 提交一次主题明确的 Git 变更；推送前确认目标仓库和分支。不要把“文件已生成”“本地已提交”“已推送”混写。

## 版本与提交

- patch：修正文字、链接与不改变判断的口径说明。
- minor：增加证据、模块或改变经营判断，并更新相关假设。
- major：重构收入分类、关键口径或整库目录，附迁移说明。
- 提交示例：`docs(ai-drama): add demand settlement evidence`。
- 本库版本写在 README；变更记入 [CHANGELOG](CHANGELOG.md)。版本号表示文档结构和内容变化，不代表证据可信度升级。

## 发布检查

所有比例都应有同口径分母；不将消耗当收入、GMV 当佣金、递延项当现金。每个“已验证”都有证据和日期。供应商当前能力及政策仅能引用经过当次核验的资料。新增模块可从 `12-<topic>.md` 起编号，并补目录。
